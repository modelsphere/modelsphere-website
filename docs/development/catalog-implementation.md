# 模型目录实现与信息可靠性清单

核对日期：2026-10-22。设计来源：Stitch 项目 `3601238558355976464`，用户确认的“模型目录-更新”，screen `5532569258885020735`。原稿只作为视觉参考，不能作为模型、认证或性能的事实来源。

审阅入口：[公开索引](https://modelsphere.github.io/model-catalog/index-v2.json)、[源仓库固定提交](https://github.com/modelsphere/model-catalog/tree/5b668ff2bfd5459ff01d3be6e26cdeac1b037f60)、[本轮设计来源](../design/sources/stitch-catalog.json)。

## 当前交付范围

- `/models`：五项统计、搜索、家族/引擎/技术标签/配方角色/硬件多选/拓扑筛选、源记录增幅/名称/配方发布日期排序、模型/配方和卡片/表格视图、分页和统一配方详情入口。
- `/models/detail?modelId=…`：模型资料和可用配方。
- `/models/recipe?modelId=…&recipeId=…`：以配方为主体，使用“部署配置 / 性能对照 / 版本历史”三个 Tab；默认部署配置，保留 SHA-256 校验、完整 YAML 复制、原始 extraArgs、历史版本与固定提交。
- `tab=performance` 展示关联测量版本、测试条件和原报告入口；`tab=history` 展示历史提交及对应配置链接。Tab 支持分享、刷新和浏览器前进后退；左右方向键及 Home/End 移动焦点，Enter/Space 激活。
- `/models/evidence`：公开的数据来源、规则解释及缺失说明。
- 配方卡片有调优记录时显示“查看对照报告”，直达“性能对照”；基线和无调优记录显示“查看部署配置”，打开部署 Tab。表格使用“查看配方详情”，点击源记录增幅直达“性能对照”。模型与配方页面通过受限的 `returnTo` 保留原目录查询；旧 `/models/report`、目录 benchmark 参数和配方 `#benchmark` 链接以 history.replace 转到配方的性能 Tab。
- 切换 Tab 保留 `version`、`dataVersion` 与 `returnTo`，不重载目录、配置或已打开的报告。报告首次打开才加载，并按所选目录中的优化配方解析最新测量版本及首份关联报告；配置历史 `version` 不作为报告版本选择，页面明确显示实际测量版本。没有报告时仍保留 Tab 并显示空态。
- 官网导航、首页 Catalog 入口和 Footer 进入站内目录；公共 Header/Footer 和双主题延续现有实现。
- 不修改 model-catalog 的源文件、生成程序或发布流水线，不创建自托管数据服务，不增加数据库和写入接口。

## 一、明确记录、有可核查来源的信息

此处“可靠”表示字段能追溯到明确的公开源文件，并不表示本站独立复测了全部性能或认证了生产环境。

| 信息 | 具体来源 | 页面处理与边界 |
| --- | --- | --- |
| 模型稳定 ID、名称、家族、简介、技术标签 | `index-v2.json` 的模型字段 | 按原值展示；名称缺失时使用稳定 ID，并归入第二类缺省 |
| Hugging Face 仓库及可选 revision | 模型 `source` | 作为来源入口；不是本站下载、托管或独立验证的权重 |
| 配方 ID、版本、所属模型 | `variants` | 模型和配方归属、路径、重复 ID 经运行时校验 |
| 引擎名称 | `engine` | 仅表示名称；不把 Chart 版本冒充引擎版本 |
| 容器镜像 repository/tag/digest | `image` | 原值展示；未提供字段不补 `latest` |
| Helm Chart 名称和版本要求 | `chart` | `>=` 为约束范围，不表示现场已安装某版本 |
| 硬件完整型号、每 pod 加速器数、节点数 | `requires` | 按来源展示；PD 配方不将 `gpus: 1` 当作完整部署总卡数 |
| 显式部署拓扑 | `requires.topology` | 展示单节点、多节点 LWS、PD 分离；缺省规则见第二类 |
| 原始部署配置和明确的启动参数 | 配方 YAML 的 `values`、`extraArgs` | 按配方 commit 读取并验证 SHA-256；复制完整 YAML，不补造一条可直接在任何站点运行的命令 |
| 配方校验值 | 配方 `digest` | 下载内容与该摘要不一致时阻止展示为已校验配置及复制 |
| 配方发布日期、Git 提交和修订历史 | `releaseDate`、`commit`、`history` | 可跳到固定提交；发布日期不是压测日期 |
| baseline/optimized 的测量版本 | `tuning.baseline`、`tuning.optimized` | 保留 `id@version`；不把旧版本测量当成当前版本复测 |
| 每种负载对应的原记录百分比 | `tuning.workloads`、`uplift` | 标为“源报告记录”；不是本站统一口径验证结论 |
| 原始性能报告 | `reports`、`tuning.report` | 提供原报告入口；结构化展示仅解析 JSON，不执行上游 HTML 的脚本 |
| 报告明确提供的 GPU、CUDA、引擎版本、测量开始时间 | HTML 中 `autotune-report-data` 的 environment/launch | 按需读取；未提供项显示“未提供” |
| 报告明确提供的输入/输出 token、SLO TTFT 分位和门槛、单请求速度下限 | 报告 `comparison.benchmark.modules[].params` | 不把这些门槛说成实测延迟或整机输出吞吐 |
| 模型数、配方数、引擎分布、有调优记录模型数、报告数、硬件类型数 | 同一已解析索引集合 | 确定性计数，包含模拟模型；22 个有调优记录模型和 23 条调优比较记录不是一回事 |
| 数据来源提交、基线采集时间和文件摘要 | 索引 `commit`；`content/catalog/baseline-source.json` | 来源数据版本、官网代码版本与读取时间分开 |

本次固定基线：28 个模型、72 个配方、22 个有调优记录的模型、23 份报告、6 种明确型号；包含一个模拟模型。源数据提交为 `5b668ff2bfd5459ff01d3be6e26cdeac1b037f60`。实时数据变化时这些计数随索引更新，文档中的数字仅描述本次审阅基线。

### 固定基线的字段覆盖率

下表只统计这份索引，不把“字段存在”扩大解释为独立复测或实际部署验证。报告和 YAML 按需读取，未逐份独立复测。

| 字段 | 明确提供 | 缺失与含义 |
| --- | --- | --- |
| 配方版本、文件 SHA-256、commit、发布日期、引擎名、镜像引用、Chart 名称 | 72 / 72 个配方 | 文件摘要与容器镜像摘要是不同字段 |
| 容器镜像 digest | 14 / 72 个配方 | 58 个未提供；只有 repository/tag 不保证镜像内容不可变 |
| 索引中的部署拓扑 | 72 / 72 个配方 | 表示来源协议中的配置值，不是现场探测结果 |
| 索引中的 defaultVariant | 28 / 28 个模型 | 本基线未触发官网“取第一项”的回退；来源默认仍不表示人工精选或官方基线 |
| Hugging Face 仓库 | 27 / 28 个模型 | 模拟模型未提供；引用地址不等于本站持有权重 |
| 索引中的权重 revision | 0 / 28 个模型 | 不把仓库地址当成已经固定到权重提交；未全量核对 YAML 中的其他权重版本配置 |
| 模型级 quantization 字段 | 1 / 28 个模型 | 其余 27 项不能从名称推成已确认量化配置，具体配方可另外查原文 |

## 二、经过规则解释、存在缺省或不宜扩大解释的信息

| 信息 | 推导/缺省方式 | 可靠性限制与处理 |
| --- | --- | --- |
| 卡片的“最佳负载”百分比 | 取该优化配方最新测量版本中已记录负载的最大百分比；没有分负载时才使用 headline | 规则可重复，但不代表所有负载、当前配方的新测量或跨模型同条件排名；卡片显示负载、测量版本和口径提示 |
| 按源记录增幅排序 | 对上述来源引用值排序，无值置后，不用 0 补齐；同值按稳定标识 | 只反映源记录大小；不命名为统一吞吐排行榜，不计算全目录中位/最高提升宣传 |
| 模型视图的卡片配方 | 优先当前匹配集合中的显式默认配方，否则按稳定 ID 取第一项 | 不自动选取最大提升作为模型性能代表；模型视图不提供模型级增幅排名，其增幅排序选项回退为名称顺序 |
| “有调优记录”与“基线”徽标 | 从 tuning 引用关系判断 | 只表示记录角色，不表示独立生产认证、当前版本复测、运行成功或质量提升 |
| 默认配方 | 优先 `defaultVariant`，缺失时沿用源协议的第一套配方 | 默认不等于官方基线；没有厂商背书时不加“官方” |
| 拓扑缺省 | 来源未指定时沿用单节点解释 | 这是协议缺省，不是检测现场部署所得 |
| GPU 简称 | 从完整设备字符串移除 NVIDIA 前缀及部分规格后缀 | 只用于视觉压缩，筛选 URL 和 YAML 保留完整型号；不能据此推算显存 |
| 名称/简介等缺失 | 名称回退为 ID；说明、镜像 tag 等显示“未提供” | 不用生成文案、零或占位数补成事实 |
| 报告解析 | 只识别当前已确认的内嵌 JSON 格式和白名单字段 | 上游格式变动或字段不全时显示失败/未提供，并保留原报告入口 |
| 网络与版本缺省 | 首访读取公开索引，失败保留固定基线；详情携带 dataVersion | 基线不是实时；无法恢复固定数据版本时明确报错，不悄悄读取最新版本 |
| 归一化或 GPU 数不同的比较 | 保留原记录百分比与原报告 | GLM 的 8→4 卡、Laguna 的 4→8 卡等不能说成同实例同条件提升；本界面未独立复测 |
| 提升条宽度及颜色 | 以 100% 涨幅为满条；0 为蓝、+50% 为青、+100% 为绿，连续渐变按实际涨幅截取；数字使用填充末端颜色，超出时封顶 | 只作相对视觉提示，不是完成率、适配等级或数值本身；保留真实涨幅文字 |

| Qwen3.6-2.4T-A96B 与 +44.8% | 基线未收录 | 不生成这张假记录 |
| CuTe Kernel、夜间自动搜索、低延迟保证等原稿宣传词 | 不存在通用、逐配方结构化支持证据 | 不按样例补造；参数/报告明确支持的内容才显示 |
| 全目录统一测试时间、完整驱动/网络/重复次数 | 索引不提供；个别报告可能有部分信息 | 不用配方发布日期代替测试日期，不补全缺失条件 |
| 实时 GPU 库存、在线状态、SLA、Telemetry Node、生产现场 | Catalog 是配置和报告目录，未提供这些实时信息 | 不展示假遥测 |

| 任意历史目录完整快照服务 | 公开源没有 `current.json/releases` 协议 | 只支持基线、当前与当前访问会话中已缓存的版本；失效有明确提示 |
| 索引中的权重固定 revision | 本次 28 个模型均未提供 `source.revision` | 不将 Hugging Face 仓库引用说成固定权重版本 |

## 数据获取与更新

`content/catalog/source.json` 集中配置公开 baseUrl、repository 和 rawBase。浏览器读取索引；配方按其不可变 commit 获取并验证摘要；历史清单在读取后截取到索引所列 digest；报告按目录 commit 读取、解析 JSON 白名单。源码和原始报告仍链接公开上游。公开源可能不可达或受其缓存影响，不承诺即时同步或国内可用性。

构建基线只服务初始 HTML 和显式降级，文件来源和摘要独立记录，不作为第二套人工维护的权威目录。未来自托管可切换数据配置；也可把目录 UI 迁移到 model-catalog，再让官网入口跳转，本期不实施这些未来部署工作。

## 验证与发布边界

按仓库 Node 24.22.0、pnpm 10.22.0、冻结锁文件安装依赖。验证包含格式、Lint、类型、全仓单测、preview/release 构建、产物检查及浏览器测试。测试 fixture 只包含本仓库显式声明的输入，测试运行不读取同级仓库；真实公开数据的网络读取另行说明。

本任务没有用户授权的推送或合并操作。没有 PR 或最终提交 SHA 时只能报告“仅本地验证，未推送/未验证远程 CI”，不能宣称可合并或已部署。具体检查结果保存在 `reports/catalog/`。
