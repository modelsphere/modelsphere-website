官网使用 Docusaurus + React + TypeScript，门户、博客和开发者文档统一构建为一个站点。Stitch 提供品牌和视觉参考；Catalog 功能、博客工作流及文档结构按本契约与[工程准则](../development/engineering.md)实现。Catalog 当前实现及数据边界见[实施清单](../development/catalog-implementation.md)；本地检查不代表生产部署或远程 CI 通过。

## 1 页面决策

| 编号 | 提案 | 影响 |
| --- | --- | --- |
| P01 | 统一站点包含首页、架构、Catalog、博客、社区、文档及详情页 | 首期不建设访客登录或内容管理后台 |
| P02 | Catalog 自定义 React UI，包含模型详情、配方历史与报告入口 | 功能覆盖现有 Model Catalog；不嵌入 Web Component 或 iframe |
| P03 | 首页和架构页按证据条件展示技术成果 | 没有证据的性能与贡献区块省略；必填基础内容缺失则阻止发布 |
| P04 | 模型目录和博客采用可分享的 URL 筛选状态 | 明确搜索字段、过滤关系、分页及非法参数处理 |
| P05 | Git 内容统一网站发布，Catalog 数据独立更新 | 博客和页面随网站提交；文档锁定来源 commit；Catalog 浏览器只读取数 |

### 1.1 内容来源与发布边界

| 内容 | 权威来源 | 页面读取与发布 |
| --- | --- | --- |
| 博客、官网文案与页面配置 | 网站 Git 仓库 | 固定提交预生成；PR 检查，合并后重建并验证正式候选，再部署同一镜像 |
| 模型、配方、测评、历史 | Catalog 数据源 | 首期直接读取公开 Catalog；运行时可更新，不触发博客构建 |
| 开发者文档与图片 | 独立 Markdown Git 仓库 | 网站锁定文档 commit，同步后进入统一 Docusaurus 构建、发布与回滚 |

博客修改通过工作分支与 PR 维护；已上线文章的新草稿留在分支，不覆盖发布分支的原文。合并后以固定提交构建全站；切换并核验成功后才记录上线。正文与预览使用同一渲染规则。

Catalog 的目录、详情、配方历史和报告绑定其数据版本；门户、博客和文档共用网站 release，文档源 commit 另行追溯。博客或首页引用性能结论时固定 Catalog 来源版本；访客不读取草稿或私有审核元数据。

| --- | --- | --- | --- |

| 技术博客与动态 | `/blog` | 博客 | 顶部新版 `3023474615820510674` |
| 社区与生态 | `/community` | 社区生态 | 保留本契约功能；本次未审阅其视觉稿 |

| 模型详情 | `/models/detail?modelId={id}` | 模型目录保持当前项 | 自定义 React 页面；继承 Catalog 的双主题 |
| 配方详情 | `/models/recipe?modelId={id}&recipeId={id}` | 模型目录保持当前项 | 部署配置、性能对照、版本历史三个 Tab，双主题 |
| 性能对照 | `/models/recipe?modelId={id}&recipeId={id}&tab=performance&dataVersion={commit}` | 模型目录保持当前项 | 配方详情的性能 Tab，保留来源版本和目录返回上下文；旧 report 路由重定向至此 |
| 文档正文 | `/docs/{docSlug}` | 文档指南 | Docusaurus 侧栏、正文与标题目录，双主题 |
| 未找到页面 | 未匹配的路径 | 无当前项 | 共享导航与双主题空态 |

本次仅以上述顶部三张新版决定首页、Catalog 和博客列表结构；其他旧稿不作为页面视觉来源。最下方深色稿仅提供主题配色，不继承其布局、内容、区块或状态。浅深主题使用同一套当前页面结构；文章详情保持独立路由。素材稿不存在完整移动端设计；响应式按交互规范执行。Header 继续使用已单独指定的项目 `14815301483114557678`，属于明确的来源例外。

- 首期语言为 `zh-CN`，路由不带语言前缀；品牌保留“模域 ModelSphere”。多语言不在本期实现范围。
- 全站路由除根路径外不带末尾斜杠，统一 Docusaurus `baseUrl: "/"`、`trailingSlash: false` 和正式 canonical。文档固定为站内 `/docs` 栏目。
- 主站结构为 `SiteHeader → main → SiteFooter`；文档使用 Docusaurus 文档布局。各页面只有一个 h1，提供“跳到主要内容”入口。
- 主导航沿用 Header 既定例外，文字与顺序为首页、全景架构、模型目录、文档指南、博客、社区生态；页面标题和 Footer 可保留“博客洞见”。文档首页为 `/docs`（`docsHomeHref`）；“快速开始”来自 `docsQuickstartHref`，部署指南来自 `docsProductionHref`。仅在真实目标可用时显示链接，否则显示“文档准备中”，不生成空链接或阻止其他官网内容发布。
- 门户与文档共用站点导航，统一由 Docusaurus 路由管理；链接保留原生 href、新窗口与无脚本导航能力。
- 主站展示页 h1 使用 `type.hero`；博客列表采用屏幕阅读器可访问的隐藏页面 h1，不增加视觉 hero，推荐文章标题为 h2。模型详情与文档采用适合阅读的标题层级。SectionHeading 承担 h2 至 h4。
- 各主页面独立设置标题、描述和分享元信息；标题格式为“页面主题 | 模域 ModelSphere”，首页为“模域 ModelSphere | 大模型推理基础设施”。
- 正式域名由部署配置提供，禁止猜测域名。可公开的门户、博客详情和真实文档进入站点地图；Catalog 参数详情页及筛选组合不生成独立索引页面，详情入口设置 noindex。
- 首页、模型目录、文档指南、博客洞见与社区生态统一使用 `CommunityFooter`：品牌介绍占两格，核心产品、社区与生态、开发者资源各占一格；底部保留版权文字，移除没有真实来源的集群状态和遥测数值。桌面五格、平板两列、手机单列，沿用社区版浅深主题与有效导航链接；不再按路由切换首页、文档和门户页脚。

所有页面均支持跟随系统、浅色、深色，包括空态、404、详情、文档和代码。主题选择不改变布局、内容或查询状态；截图中的头像不代表登录功能，Star 与状态数字不得使用占位值。

## 3 页面数据和区块约定

主站展示页输入包含 `meta`、本页专用内容及其契约要求的 `hero`；博客列表、详情与文档不强制 hero 区块。`meta` 包含标题、描述，`hero` 包含标题、简介和操作入口；首页最多三个，其他页面最多两个。页面数据由页面传入组件，组件不自行查询数据。

下表中的“必填”表示发布该页面的前提，不满足时校验失败；“条件”表示满足明确条件才展示，未满足时移除区块及相应入口，不留下空白占位。“空态”表示保留页面骨架，并展示 ContentState。

所有区块按表格顺序输出。区块 id 在该页唯一且稳定；移除条件区块时同步移除指向它的入口。只有明确标为 wide 的区块可使用 1440px 容器，其余均使用 default；Catalog 表格与测评区允许 wide。

文档目标未就绪时，CTA 只显示真实可用的替代入口或准备说明；缺少可选文档链接不阻止主站发布。

正文图片、Logo 和架构图保留固有比例，使用完整图片展示。文章封面预留推荐 16:9、列表 3:2 的展示比例，仅在有审核过的裁剪预览时使用 object-cover，不能裁去理解内容必需的信息；没有审核预览则使用 object-contain，悬停不放大图片。文章正文保留完整原图。视频、图片轮播和自动播放不属于默认页面能力。

## 4 官网首页

目标：解释平台用途，使访问者进入快速开始、了解架构或查看模型配方。

| 顺序与 id | 内容输入与数量 | 组合 | 发布规则 |
| --- | --- | --- | --- |
| 1 `hero` | 左对齐定位标题、简介、技术标签、系统架构概览 | 页面 h1、ActionLink、DiagramFrame | 必填；三个入口为 `docsQuickstartHref`（真实内容就绪后）、已核实 GitHub 源码仓库、`/models`；首屏完整直出，首页文字按 D13 入场、拓扑正文按 D14 一次纵向揭示；入口、拓扑标题及上方三卡静态可用，数据与布局稳定 |
| 2 `comparison` | 4 项能力：生产部署、异构硬件、快速调优部署、持续优化；各含标题、说明与能力面板 | SectionHeading、4 个 FeatureCard | 必填；桌面/平板 2×2，手机纵排；不增加独立四项 Tab |
| 3 `fault-tolerance` | 断流续写的探测、上下文接续、前提与限制 | SectionHeading、DiagramFrame、分步说明 | 条件：有可核实的机制资料与 Claim；不承诺无条件零中断 |
| 4 `qos-scaling` | QoS 限流与 SLO 弹性伸缩两项机制 | SectionHeading、2 个机制卡与图示 | 条件：有实现资料；区分目标、示意与实测，不输出模拟实时遥测 |
| 5 `autotune-evolution` | 线上服务、流量收集、空闲算力调优、配置验证、自动上线的五步闭环 | SectionHeading、DiagramFrame、步骤说明 | 条件：有对应实现资料；标明适用范围，不把调优闭环当作请求执行流程 |
| 6 `benchmarks` | 最多 4 条有完整条件的 baseline/candidate 比较记录 | 紧凑 BenchmarkTable、ActionLink | 条件：至少 1 条合格记录；指标、条件、来源同表可读，入口指向 `/models/recipe?modelId={modelId}&recipeId={recipeId}&tab=performance&dataVersion={sourceVersion}` |
| 7 `get-started` | 居中接入邀请与社区入口，手机纵排操作组 | CtaBlock | 必填邀请；真实快速开始就绪后使用 `docsQuickstartHref`，否则显示准备说明和 `/community` |

Hero 只展示新版单张完整系统架构图，浅深主题表达相同信息并保持同一框尺寸；不预置监控标签、双 Tab、隐藏面板、Live UI 或轮播。真实产品截图属于后续修订规格的事项。首页不再设置独立 `features` 四项 Tab、`request-flow`、`audiences` 或推荐文章区块；架构页及其他页面的既定功能保留。

首页不在本地重新计算性能提升比例；所有能力摘要、机制图和测评均引用内容与证据规范认可的记录，不按设计稿补造结果。

## 5 特性与架构

目标：解释模块边界、一次请求的执行路径和关键机制，提供进一步阅读入口。

| 顺序与 id | 内容输入 | 组合 | 发布规则 |
| --- | --- | --- | --- |
| 1 `hero` | 架构定位与适用场景 | 页面 h1、ActionLink | 必填；主要入口为配置 `docsProductionHref`（内容就绪后） |
| 2 `principles` | 3 项有依据的架构原则及说明 | SectionHeading、FeatureCard | 必填；不把营销形容词当技术保证 |
| 3 `topology` | 接入防护、路由、缓存、计算实例、控制面五个层次 | DiagramFrame、TabGroup、分层文字说明 | 必填，wide；标明实现状态及对应代码或文档入口 |
| 4 `continuity` | 断流续写前提、步骤、限制与失败行为 | SectionHeading、DiagramFrame | 条件：有可核实的机制说明；不得默认承诺零中断 |
| 5 `slo-scaling` | 限流、动态队列与弹性联动 | SectionHeading、FeatureCard、DiagramFrame | 条件：有实现资料；清晰区分目标指标和实测指标 |
| 6 `autotune` | 调优闭环、候选配置、线上验证关系 | DiagramFrame；有数据时加 BenchmarkTable | 条件：有调优流程资料；表格另须具备完整测试证据 |
| 7 `contributions` | 上游贡献与算子优化条目 | FeatureCard、来源链接 | 条件：至少 1 条可核实记录；明确区分已提交和已合并 |
| 8 `deploy` | 部署下一步 | CtaBlock | 必填；指向 配置 `docsProductionHref`（内容就绪后） |

各机制区块不使用占位吞吐图或随机遥测动画。总体架构图中规划中能力必须标为规划中；内容规范将规定状态证据要求。

## 6 Model Catalog

功能依据为 [Model Catalog](https://modelsphere.github.io/model-catalog/) 及其[源码](https://github.com/modelsphere/model-catalog)。实现时记录核对 commit，逐项映射功能；使用官网设计变量与自定义 React + TypeScript 组件，不嵌入 `<model-catalog>` 或 iframe。

| 页面/区域 | 内容与操作 | 数据与状态 |
| --- | --- | --- |
| `/models` 概览 | 搜索、家族/引擎/标签/硬件/拓扑筛选、排序、卡片/表格切换、模型/配方视图 | 默认展示配方；模型和配方是不同实体；显示数据版本及更新时间 |
| 模型详情 | 模型说明、来源、可用配方、硬件与引擎组合 | 主标题链接到模型详情；构建后新增模型无需重发主站即可访问 |
| 配方详情 | 统一配方摘要与部署配置、性能对照、版本历史三个 Tab | 保留稳定模型/配方 id 和精确版本；不在网站仓库另建权威编辑源 |
| 配方“性能对照”Tab | baseline/candidate、指标口径、BenchmarkTable、测试条件与原报告入口；无报告时显示空态 | 只有来源支持时展示提升结论；未知条件明确标注，不填造数据 |
| 贡献入口 | 已核实的仓库贡献指引 | 官网只读，不增加公开写入或发布模型能力 |

视觉结构：标题与数据版本 → 可核实统计 → 搜索/筛选工具栏 → 目录/配方卡片或表格；对照报告在对应配方详情的性能 Tab 阅读。统计最多 5 项，模型数/配方数从同版集合计算；优化组合数、中位/最高提升只有口径、样本集合和可比性均有依据时展示，否则省略，不混合不同硬件/负载得出营销结论。

Catalog 卡片桌面最多 4 列、平板 2 列、手机 1 列；硬件使用 checkbox 多选语义与可换行 chip 外观，选中项有文字及勾选状态。卡片标题进入对应模型或配方详情；配方卡片主入口按调优记录显示：有调优记录为“查看对照报告”，直达性能 Tab；基线或无调优记录为“查看部署配置”，打开部署 Tab；表格入口为“查看配方详情”，默认打开部署配置；源记录增幅使用原生链接直达同一配方的性能 Tab。复制为独立按钮，卡片有多个操作时禁止整卡点击。浅深主题都有相同测评入口和详情能力。

顶部新版未画出的模型/配方视图切换、拓扑筛选、硬件多选状态、分页及完整测评详情属于保留的工程补充，实施时仍需覆盖，不因静态稿省略而删除。默认配方卡片与四列密度沿用新版视觉。

视角选择器常驻筛选行，位于模型家族之前，选项为“模型视角 / 配方视角”；切换保留已有查询条件。模型卡片的“可用配方”采用无边框、无色块的行内计数，标签使用 muted 文字色和 12/20px，数字使用品牌主色和 16/20px，视觉层级低于模型标题；两主题共用尺寸和结构，数量不展开为配方列表。

目录筛选、排序、视图切换和硬件选项的桌面高度统一为 32px，手机为 44px；搜索框单独使用桌面 40px、手机 48px，输入框与内部搜索按钮垂直居中。模型卡片与配方卡片共用四列 / 两列 / 单列响应式网格。

查询契约采用官网统一命名，数据适配器负责映射来源字段：

- `q`：模型名称、简介、稳定标识，以及配方名称、镜像与硬件名称的大小写不敏感连续匹配；模型视图可由关联配方字段命中。去除首尾空白，最多 100 个用户可见字符，提交后生效；仅匹配来源实际提供的字段。
- `family`、`engine`、`tag`：单选稳定标识；`hardware`：多选，使用重复参数表示，匹配任意已选硬件；筛选组之间为 AND。
- `topology`：单选 `single-node / leader-worker-set / prefill-decode`，适配器将源拓扑映射为这些值。
- `view`：`models / recipes`，默认 recipes；`layout`：`cards / table`，默认 cards；切换不丢失共同筛选条件。
- `sort` 默认 `improvement-desc`，本期只比较已明确标注的源记录最佳负载百分比，保留条件和测量版本，不解释为统一吞吐性能排名；另支持 name-asc/name-desc/updated-desc。无值置后，同值按稳定 id。模型视图按“调优配方最佳提升”排序并展示对应 baseline、负载和版本，模型卡片仅显示可用配方数量，完整配方在模型详情和表格中展示，不复用默认配方卡片。
- `page`：默认 1，每页 12 条；先过滤再排序和分页。初始 HTML 提供完整精简列表与原生详情链接，增强成功后接管交互。
- 配方页：`tab` 为 deployment / performance / history，缺省或未知值显示部署配置。切换保留配方身份、`version`、`dataVersion` 与 `returnTo`，支持分享、刷新及前进后退；方向键和 Home/End 移动 Tab 焦点，Enter/Space 激活。
- 性能 Tab：`modelId`、`recipeId` 定位优化配方，`dataVersion` 固定目录提交；展示该目录中配方最新测量版本关联的首份报告，不支持任意配方比较或历史报告选择。参数不完整、记录不存在、无关联报告和目录版本不可用分别提示，不替换为其他记录。
- `returnTo`：模型、配方和报告页传递原目录查询，仅允许站内 `/models` 地址，保留搜索、筛选、视图、排序及页码；缺省或无效时返回 `/models`。报告的 `dataVersion` 不写回原目录查询。
- 旧 `/models/report?…`、`/models?benchmark={modelId}/{recipeId}…#benchmark` 和 `/models/recipe?…#benchmark` 链接以 history.replace 转入配方性能 Tab；移除返回地址中的旧 benchmark，避免返回循环。
- 配方页 `version` 固定配方历史版本；可选 `dataVersion` 固定目录快照。省略时读取当前公开版本并展示解析到的版本；固定版本不可用时明确报错，不静默切到最新；公开源完整快照能力限制以工程规范第 5.1 节为准。

“按性能提升排序”表示各记录相对各自基线的已核验吞吐增幅，不是跨模型绝对性能排行；来源版本、指标口径及可比性判断遵循[内容与证据规范](content-policy.md#5-性能测评)。不得把不同模型、硬件或工作负载排序结果宣传为同条件比较。

id 使用来源的稳定标识，由适配器进行 URL 编码与反解，不按标题自行重造；模型存在但来源不可用属于加载错误，不能当作 404。未知模型/配方在来源成功确认不存在后显示“未找到”，固定页面仍为 HTTP 200；来源接口状态与网站页面状态区分。首期报告和数据使用现有公开来源，固定提交读取配方并核验摘要；后续再切换自有服务。

### 6.1 静态路由与无脚本边界

Catalog 模型详情的身份参数为 `modelId`，配方页为 `modelId` 和 `recipeId`；可选 `dataVersion` 固定数据版本，`version` 固定配方版本。列表跳转时携带已解析的数据版本。固定详情页在构建时生成，新增模型可在数据发布后直接访问，不需要重建网站。

`/models` 初始 HTML 可读构建时的基线摘要，并标记版本与时间；客户端加载当前数据后才切换到实时结果。无脚本模型/配方/报告详情只提示需要 JavaScript 并提供返回目录及已核实来源入口，不承诺实时详情正文。静态服务器对详情入口返回 200，缺少参数或记录不存在由页面提示；首期不承诺动态模型独立搜索收录或分享卡片。

## 7 开发者文档

目标：将开发者维护的 Markdown 仓库转换为标准、朴素、可检索的网页文档。采用同一 Docusaurus 应用的 docs 插件，与门户和博客统一构建发布。

| 区域 | 规则 |
| --- | --- |
| 顶部导航 | 全站品牌和主导航、必要文档入口；不使用营销 hero 或 CTA 大区块 |
| 侧栏 | 按实际 Markdown 内容和导航配置组织；无真实内容的分类不生成虚假页面 |
| 正文 | 标题、段落、列表、提示、表格、代码块及图片，默认普通 Markdown |
| 标题目录 | 桌面辅助定位，窄屏可折叠；语义与键盘操作完整 |
| 搜索 | 自托管索引，与正文同版发布；具体插件按兼容性确定 |
| 阅读辅助 | 代码复制、上一页/下一页与有效来源链接；无装饰入场动画 |

文档内容可包含快速开始、生产部署、验证和故障排查；具体命令、前置条件和适用版本从实现资料核验，不从设计占位内容生成。首期不强制多版本与多语言，不生成空版本入口。

开发者在源仓库通过 Git PR 维护内容，合并后更新网站锁定 commit；网站 PR 检查、合并后重建并验证全站候选，提升同一网站产物。文档更新会重新构建网站，但不会引入未合并的博客草稿；失败保留整个旧站。

技术文档源为网站仓库的 `content/docs/`，新增 Markdown 自动进入侧栏、正文和搜索。当前两篇阅读示例保留正文说明；快速开始在实际存在 `/docs/quickstart` 时启用，否则指向 `/docs`。文档使用全站正式域名与 `/docs` 栏目，部署到 GitHub Pages 时沿用项目 baseUrl。显式设置 `DOCS_SOURCE_MODE=none` 后显示文档准备状态。

## 8 技术博客与动态

目标：提供真实发布的技术文章、版本动态与实践记录。

| 顺序与 id | 内容输入 | 组合 | 发布规则 |
| --- | --- | --- | --- |
| 页面标题 | “博客洞见”等页面级标题 | 屏幕阅读器可访问的隐藏 h1 | 必填；保留页面语义，不增加独立视觉 hero |
| 1 `featured` | 0 或 1 篇指定推荐文章，推荐标题为 h2 | ArticleCard，16:9 封面；审核预览可裁剪 | 条件：推荐文章已发布且目标有效；无筛选的第 1 页开场展示 |
| 2 `posts` | 搜索、单选分类、热门标签与文章列表 | SearchField、分类按钮、标签筛选、ArticleCard、分页链接 | 空态：尚无公开文章；筛选无结果时提供清除筛选；列表封面 3:2 |
| 3 `channels` | 微信技术群与知乎专栏的可选侧栏 | 已核实渠道卡、二维码及文字入口 | 条件：对应真实配置与目标可用；桌面位于列表右侧，窄屏移至列表后；缺失不留空位 |

- URL 参数为 `q`、`category`、`tag`、`page`；q 匹配标题、摘要、作者、技术关键词、标签显示名与 PR 编号，大小写不敏感连续匹配，去除首尾空白，最多 100 个用户可见字符；PR 使用已登记的纯数字、`#数字` 或 `owner/repo#数字` 形式，可选字段缺失时不补造文本。
- category 与 tag 各为单选稳定标识，tag 映射文章 tagIds 与真实标签字典，q/category/tag 之间使用 AND；选项来自全部已发布文章及真实配置。热门标签按全部已发布文章引用数降序、同值 id 升序取前 10 项，推荐文章只计一次；点击提交 tag，再次点击已选标签清除 tag，可见状态与可访问状态一致。每页 12 篇，按发布日期降序，同日按 id 升序。
- q、category 和 tag 均为空时，所有页共用排除推荐文章后的列表集合；在此集合上排序、计数和分页。推荐区仅在第 1 页显示。存在任意搜索、分类或标签条件时，不显示推荐区，列表在全部已发布文章中筛选，允许推荐文章作为普通匹配结果出现。
- 文章可以是站内正文或外部文章；外部文章直接使用其原始链接，不同时生成空白站内详情。
- 站内文章 slug 使用小写英文字母、数字和单连字符；唯一且发布后保持稳定。改名须保留旧地址重定向。

渠道卡只展示真实群入口、二维码、专栏与维护说明；二维码提供同设备可用的文字入口或加入说明，不生成模拟二维码、联系人、赠品或更新承诺。作者、阅读时长与任何统计均来自已核实配置或数据；关注数还需来源与 observedAt，没有来源时省略，不引入未定义的追踪、注册或登录功能。

文章详情结构为：面包屑/返回博客 → h1 → 发布日期与可选作者、分类、有来源的作者标注阅读时间 → 可选封面 → 正文 → 来源 → 最多 3 篇相关文章。阅读时间缺失时省略，不自动估算。桌面采用左侧章节目录、中间正文、右侧关联资源；外层沿用全站 `--page-gutter` 左右边距，不另设最大宽度，侧栏各 200px、间距 24px，正文填满其余可用宽度。两侧内容允许缺省，不保留空卡位。<1280px 时目录折叠到正文前、关联资源移到正文后，正文填满外层容器。

章节目录由真实标题生成，当前章节使用 aria-current；吸顶偏移随 Header 高度变化。可选阅读进度只按文章正文范围计算，0–100% 限幅，短文不足一屏时隐藏；提供可访问名称，不逐帧播报、不以进度驱动滚动。复制链接使用当前正式 canonical 与 fragment，遵循复制反馈规则；不增加收藏、点赞、登录或假计数。关联仓库、配方和社区入口须真实可用；没有资料时省略。

博客列表由推荐文章、筛选与分页卡片及有真实配置的渠道侧栏组成，详情单独路由。推荐和列表封面按审核后的裁剪预览展示，正文图片与架构图完整显示。正文不采用营销卡片大字号；代码、引用、提示、表格和图片都有主题对应表面。

详情复用 CodeBlock、DiagramFrame 和受控正文渲染器；标题、列表和引用采用语义化 HTML，不另外复制博客卡片样式。相关条目由文章 id 配置。发布日期、摘要和标题与列表使用同一记录；不存在或未发布的 slug 返回 404。

博客由作者通过 Git 编辑 Markdown、frontmatter 和相对图片；支持将已有 `.md` 连同图片加入仓库，不设置后台上传按钮。PR 检查与预览后合并，针对合并 SHA 构建正式候选并发布；Git 保留修订。撤回和恢复也通过 Git 变更及全站构建完成，覆盖列表、详情、搜索、RSS（如启用）与相关资源。

## 10 空态与失效地址

| 场景 | 处理 |
| --- | --- |
| 必填页面内容或必填链接缺失 | 内容校验失败，阻止发布该站点版本；预览指出缺失字段 |
| 条件区块无合格内容 | 移除区块及其跳转入口 |
| 模型或文章集合为零 | 返回正常页面，显示尚无公开内容；不当作接口异常 |
| 搜索筛选无结果 | 保留条件，显示无结果及清除筛选操作 |
| 非法家族、引擎、标签（含博客 tag）、硬件、拓扑或分类值 | 忽略该项，恢复不限，展示一次可读提示并规范化 URL |
| page 非正整数 | 按 1 处理；超出末页则归一到末页，零结果时为 1 |
| q 超过 100 字 | 页面和 URL 统一截取前 100 个用户可见字符，并显示提示 |
| 未知参数 | 不参与筛选；重复的单值参数只取第一个值；hardware 收集合法值并去重 |
| 未知静态路径、博客或文档已撤下 | 返回真实 HTTP 404，保留公共布局及返回首页、文档入口 |
| Catalog 参数缺失或记录不存在 | 分别展示参数错误或未找到；固定详情入口 HTTP 200，不伪称服务端 404 |
| Catalog 请求或本站数据文件加载失败 | ContentState error 与重试，保留可读基础内容；不能伪装成空集合 |

博客与文档预生成正文，Catalog 运行时取数提供真实加载和失败状态；资源失败不使用虚构结果兜底。主页面与详情的直接访问、刷新和带参数链接均必须有效，不能只在客户端跳转时可用。

## 11 实施与验收边界

1. 只生成已批准页面及模板；新增路由、业务字段或区块先修订契约。
2. 主站共用 Header、Footer 和设计变量；站内文档采用标准正文布局，共享导航与品牌配置。
3. 页面中的所有链接指向本契约路由、真实锚点或已核实的外部地址。
4. 首页与架构页隐藏条件区块后，页面阅读顺序和导航仍完整。
5. 模型与博客的搜索、筛选、分页、复制 URL 和直接访问得到一致结果。
6. 已发布站内文章有真实正文；外部文章不产生空详情页。
7. 1280 / 1440px 是内容宽度上限；不使用截图高度或固定整页高度限制内容。
8. 首页、Catalog 与博客列表按顶部三张新版及本契约验收；文章详情、模型/配方详情、其他页面和 404 按既定功能与共享规范实现并单独验收，不从旧稿继承结构。深色继承同一结构，仅使用核对后的主题配色。
9. 所有页面均检查浅深模式、三态偏好及切换后的输入/查询/阅读位置；不能只验首页主题。

当前首页、博客、Catalog 与文档试点已本地实现；真实内容同步和生产接入仍待完成。Catalog 的本地验证记录见实施清单，远程 CI 未验证。
