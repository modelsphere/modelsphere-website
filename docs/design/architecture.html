01当前决策
DECISION

一个 Docusaurus 站点，Git 内容发布，Catalog 独立取数

门户、博客、社区和开发者文档使用一个 Docusaurus + React + TypeScript 应用。门户与 Catalog 使用自定义 React 页面，博客由 Markdown/Git 维护，文档采用标准侧栏与正文布局。所有网站内容统一生成静态文件，封装一个 Nginx 镜像，部署到现有 Kubernetes。

Catalog 模型、配方、测评与历史仍由源系统维护。首期按用户决定直接读取公开 GitHub Pages / raw GitHub，来源地址集中配置，后续再接自有服务。内容更新与网站代码发布可以分开；不嵌入 <model-catalog> 或 iframe。

已确认的范围

博客首期通过 Markdown/Git 发布。无需内容管理后台、数据库、素材上传服务或自建发布队列。文档内容仓库可以独立，但文档网页与门户属于同一个部署产物。

当前仓库已本地实现首页、博客、文档试点与 Catalog 公开源接入。本图仍包含后续目标；真实内容同步与生产部署尚未实施，远程 CI 未验证。Catalog 数据边界见 信息可靠性清单。

职责技术边界
门户与社区React + TypeScript + CSS遵循已有视觉、组件与交互规范
博客Git Markdown + Docusaurus blog 插件自定义列表，保留 I05；正文预生成
文档指定 Git commit + docs 插件站内 /docs，朴素阅读布局
Catalog自定义 React + 独立只读源动态数据不进入第二套编辑系统
生产交付静态 build/ + Nginx + Docker/KubernetesNode.js 仅构建时使用

03页面与内容
RENDERING

门户定制外观，文档保留标准阅读结构

路径生成方式无脚本表现
/、/architecture、/community自定义 React 页面静态生成正文、导航与图示可读
/blog、/blog/{slug}博客插件与自定义列表完整摘要列表与文章正文可读
/docs、/docs/{docSlug}文档插件标准侧栏、正文、标题目录；搜索依赖脚本
/models自定义 React + 构建基线基线摘要可读，标记版本与时间
/models/detail、/models/recipe固定 React 页面 + 身份查询参数提示实时详情需要 JavaScript

全站同域，baseUrl: '/'、trailingSlash: false，首期中文无语言前缀。共用导航和品牌配置，文档正文不套用营销 hero 或装饰入场。图片、字体、脚本、代码高亮和搜索资源随构建或自托管交付。

首页按 hero → 四张同时展开的能力卡 → 断流续写 → SLO → Tuning-Agent → 最多四条合格测评 → 渐变 CTA 排列；不强制增加四项能力标签、五步请求、三类受众或文章网格。门户 Footer 四组统一为“开源代码／社区与生态／开发者资源／法律与开源”，博客入口仅放社区组；已实现文档双层 Footer 保留为既定特例。

网站根目录 docs/design/ 与 docs/development/ 是内部规范，不能成为 docs 插件的默认公开输入。插件只读取经过校验的生成目录；主题只做必要包装与定制。

04博客维护
BLOG

博客通过文件、预览与 Git 发布

作者在本地编辑器或 Git 平台维护 content/blog/<id>/index.md 和相对图片。frontmatter 描述标题、摘要、日期、slug、作者、分类、真实标签、技术关键词、PR 引用与来源；已有 Markdown 可按同一约定加入仓库。没有网站后台上传、账号管理或发布 API。

Docusaurus blog 插件负责正文和详情路由，自定义列表保留网站设计与 I05。使用 postsPerPage: 'ALL' 和自定义 blogListComponent，初始摘要索引包含标题、摘要、作者、关键词、PR、分类与标签等列表及查询字段；不得导入全文或正文组件。推荐文章优先展示，不另加独立视觉 hero，页面 h1 可视觉隐藏但保持可访问。微信／知乎侧栏仅在真实资源配置后展示。

内容规则行为
未筛选列表所有页排除推荐文章，每页 12 篇，推荐区仅第一页显示
搜索、分类或标签从全部文章匹配，推荐文章可作为普通结果出现；分类与 tag 为 AND
搜索字段标题、摘要、作者、关键词、标签名及 PR 编号／owner/repo#编号；无需加载正文
封面无审核裁剪预览时 contain；审核后推荐 16:9、列表 3:2；正文完整，hover 不放大
无脚本全部公开摘要与原生链接可读；增强成功后再分页
草稿保留工作分支或通过构建前过滤排除；不能只隐藏列表入口
修改已上线文章新草稿留在分支，主分支保留线上正文，避免其他发布意外撤下
撤回和恢复Git 变更、全站校验和构建；检查详情、摘要、引用、搜索与资源

正式内容只接受普通 Markdown；拒绝原始 HTML、可执行 JSX、import 和表达式，校验链接协议及相对路径。普通 Markdown 模式不等于自动完成安全检查。源码、fixtures、草稿图片和审核记录不能进入公开产物。

05开发者文档
DOCS

固定文档源提交，随网站统一发布

独立文档仓库由开发者维护。网站的 content/docs-source.lock.json 记录仓库地址、完整 commit 和内容子目录。源仓库合并后，由维护者更新网站锁定文件并提交 PR，首期不假定跨仓库自动触发已存在。

构建只同步正文、图片及约定导航元数据到 .generated/docs/，拒绝越界路径和符号链接，不执行源仓库提供的插件或脚本。源仓库分支的后续变化不能改变当前已锁定的构建输入。

情况处理
目前没有真实文档/docs 为准备页，不生成假教程，不加入搜索与站点地图
首批真实文档到位移除准备页路由注册，由 docs 插件接管，避免路由冲突
源 commit 更新统一构建门户、博客和文档；正文、资源与搜索索引同版
文档校验或构建失败整个候选停止发布，线上旧网站保持可用
网站回滚同时恢复博客和文档，保留各来源 commit 以便追溯

只在内容需要时启用多版本、多语言，首期没有空版本目录。快速开始与生产部署链接只在真实页面存在时显示。

06模型目录
CATALOG

自定义 React 保留功能，参数路由适配静态部署

按源系统建立功能映射，覆盖模型/配方视图、搜索、家族/引擎/标签/硬件多选/拓扑筛选、排序、卡片与表格、模型和配方详情、历史、配置复制、测试条件与报告。数据协议和复用许可在实现时核验，不能把几张模型卡片当作集成完成。

默认 view=recipes、layout=cards、sort=improvement-desc，q 包含配方、模型、镜像与硬件。新稿未展示的模型视图、拓扑、历史及详情等作为工程功能补充。排序引用源报告记录的最佳负载增幅，保留测量版本与条件；无值置后，不补零，不表示统一吞吐或跨模型同条件排名。统计卡不发布全目录中位或最高提升宣传。

浏览器先读取公开索引，配方按不可变 commit 下载并校验摘要，报告按目录 commit 解析 JSON。列表链接携带 dataVersion；当前公开源没有任意历史快照接口，只支持基线、当前与会话缓存版本，固定版本不可用明确报错。后续自有服务上线时再切换适配器配置。

入口参数与行为
/models/detailmodelId 必填；dataVersion 可选；固定页面支持构建后新增模型
/models/recipemodelId、recipeId 必填；version、dataVersion 可选；校验配方归属
参数不存在或记录缺失页面分别显示参数错误或未找到；静态入口 HTTP 200
来源不可用真实错误、重试或明确标注时间的已有数据；不能伪装为空集合
无脚本目录可读构建基线，显示版本和时间；实时详情提示脚本要求
静态部署的明确边界

首期不承诺动态模型逐条搜索收录、独立分享预览图、按查询参数返回 HTTP 404 或实时无脚本详情。详情入口预生成 noindex；未知网站路径、未知博客和文档仍返回真正 HTTP 404。

Catalog 数据更新不触发博客发布。基线更新需要网站构建；构建基线未更新不阻止客户端访问新数据。网站回滚前须确认旧界面与当前数据协议仍兼容。

07发布流程
RELEASE

合并后验证实际提交，部署同一个候选镜像

使用现有 CI 与部署环境记录检查、预览、镜像和上线状态，不自建数据库发布状态机。作者可以自行核对内容，不额外增加第二人审批；实际权限仍遵循仓库和环境保护规则。

  1. 分支修改 → PR 内容校验与代码检查 → 全站预览。预览对应明确 SHA，不因源分支移动而无声改变。
  2. 合并后针对实际提交重新检查，锁定文档 commit、Catalog 基线、依赖和配置，构建正式候选。
  3. 验证候选页面与资源，记录 digest；部署时复用同一镜像，不重新拉取内容或安装依赖。
  4. 每环境串行发布，切换前确认候选仍是选定提交，较旧任务不能覆盖已经上线的新版本。
  5. 就绪检查后切换入口，核验公开路由、版本和资源；成功才记已上线，失败保留或恢复旧网站。

PR SHA 与合并 SHA 不同时，旧检查和旧产物不能充当正式发布证据。完整候选预览保护 HTML、数据与素材，设置 noindex；只隐藏链接不能保护未公开内容。

内部发布清单目的
网站完整 Git SHA绑定代码、博客、配置和文档锁定文件
文档仓库 / commit / 路径追溯外部内容输入；无真实文档时为空
Catalog 基线版本 / hash / 契约版本保证构建基线可重现，独立于实时版本
锁文件 / 配置 / 产物摘要防止候选输入无声变化
镜像 digest 与 CI/部署记录证明验证和上线的是同一产物
08生产部署
DEPLOYMENT

生产仅运行静态网站，复用已有基础设施

组成职责待核验
Nginx 网站镜像提供 Docusaurus build/，非 root，无数据库密钥实际生成文件布局、直达路由、404、缓存
Ingress 与 TLS统一站点入口，可转发同源 /catalog-data/正式域名、路由、集群配置
CI 与受控预览GitHub Actions 文档试点检查已配置；全站流水线后续扩展远程运行、仓库权限、预览保护
Catalog 数据托管版本化静态文件或只读接口数据协议、同步方式、维护方和 CORS
私有镜像与产物归档发布追溯和恢复现有镜像仓库、保留策略

首期不新增 PostgreSQL、Redis、对象存储上传服务或常驻发布消费者。图片随 Git 和构建交付；后续存在真实大文件需求时再接独立存储，不能预设某种存储协议。

生产 Nginx 按实际输出查找静态页面，未命中返回 404；不配置全站首页回退。Node.js 仅用于构建，版本与 CI、Docker 构建阶段一致。国内外访问均不依赖海外字体、图片、脚本或实时 GitHub 请求。

09撤回与恢复
RECOVERY

网站整体回滚，撤回同时处理内容资源

网站回滚恢复同一个历史镜像中的门户、博客和文档；Catalog 实时数据不随网站回滚。回滚前验证旧界面对当前数据契约的兼容性，并阻止已经撤回的文章或声明重新出现。没有旧版本的首次发布失败保持未上线。

撤回通过 Git 变更和全站重建完成，清理原文、摘要、推荐、相关文章、搜索与 RSS。Docusaurus 的内容也可能存在于客户端 JS 中，因此不能只删除 HTML。保留旧代码块供旧页面使用时，必须识别并移除带撤回正文或素材的资源。

资源规则
HTML 与内容数据可重新验证缓存，撤回时清理代理缓存
正文 JS、图片、搜索与 RSS纳入公开产物审计，撤回后不能由旧 URL 继续提供
纯代码、字体与图标按内容 hash 缓存；确认不携带正文后才长期保留
历史镜像与发布清单私有归档，不公开历史站点目录

用户已经下载的内容与第三方转载无法追回。Git 历史也不提供保密能力，不能提交私密资料后依赖普通撤回消除；修改历史和删除归档属于另行确认的操作。

10实施与验证
VALIDATION

先验证内容和数据两条流程，再铺开页面

  1. 延续已完成的两篇 Mock 文档试点、依赖锁定、Nginx 路由及本地验证；远程 CI 尚未验证，搜索插件仍待接入。
  2. 用隔离的一篇示例文章验证文件输入、摘要索引、分类/标签查询、PR 预览和统一构建；示例不作为正式内容发布。
  3. 用真实 Catalog 样例验证协议、自定义界面、版本读取、固定详情页和构建后新增模型访问。
  4. 接入真实文档仓库前先约定源格式与锁定文件；有真实内容后接管 /docs，不公开内部设计规范。
  5. 按顶部三张新版与当前页面契约实施门户，完成浅/深主题、跟随系统、响应式、键盘、减少动效、资源失败与实际静态服务测试；本次规范修订不表示这些页面已实现。
验收重点通过条件
博客 I0525 篇含 1 推荐，无筛选两页各 12，无重复遗漏
静态基础文章/文档无脚本可读，未知静态路由真实 404
Catalog 动态能力构建后新增记录可直达，版本固定、失败与乱序正确反馈
统一主题首访系统偏好与太阳／月亮切换由 Docusaurus 统一管理；首帧正确，跨页与切换不丢查询/输入/阅读位置，代码和图表均适配浅深色

CI 证据核验实际最终 SHA 和所有适用检查，不用本地结果代替远程 CI
证据边界

当前应用已锁定依赖并配置本地检查与 CI；Node 24.22.0、pnpm 10.22.0、Docusaurus 3.10.2、React 19.3.1、TypeScript 5.9.3 及构建参数校验已落地。Catalog 已完成公开源接入，验证记录见实施清单；远程 CI 尚未验证。真实内容同步与生产部署仍待实施，本地预览不代表已经发布。

视觉依据：当前 Stitch 项目 顶部“首页-更新”“模型目录”“博客洞见-更新”三张；底部旧稿仅补充 dark mode 色彩。Header 保留 独立项目覆盖，文档双层 Footer 保留既定特例，不继续读取旧页面结构。全站统一 Space Grotesk / Geist / JetBrains Mono，Header 的 Inter 为既定例外；同一结构与语义变量映射 Docusaurus、Prism 和自定义 Catalog。报告自身排版不作为产品 UI 模板。

实现依据：开发准则、页面契约、内容与证据规范、交互规范。
